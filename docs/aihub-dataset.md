### 라벨 JSON 스키마 (실물)

```json
{ "group_no": 602011001000, "no": 602011001001, "img_no": 1,
  "cate1": "배", "cate2": "신고", "cate3": "특",
  "width": "10.6", "height": "8.3", "weight": "556",
  "img_width": 1000, "img_height": 1000, "format": "png",
  "angle_direction": "top", "verticality_angle": 0, "horizontality_angle": 45,
  "bndbox": { "xmin": 0, "ymin": 0, "xmax": 1000, "ymax": 1000 } }
```

`group_no` 가 **실물 개체 ID**다. 분할·집계는 반드시 이 값을 기준으로 한다.
`bndbox` 는 항상 이미지 전체라 검출용이 아니라 분류용이다. 해상도는 전량 1000×1000.

### ⚠️ 등급은 크기·중량이 사실상 좌우한다

라벨의 실측 중량만으로(사진을 아예 안 보고) 등급을 맞혀 보면:

| 품목 | 중량 단독 정확도 |
|---|---|
| 양파 | 89.2% |
| 감자 | 81.5% |
| 사과 | 65.5% |
| 감귤 | 64.6% |
| 배 | 60.8% |

즉 이 데이터의 '등급'은 상당 부분 **크기 등급**이다. 사진 한 장에는 크기 기준물이 없으므로
이미지만으로 등급을 맞히는 것은 원리적으로 상한이 있다.

**→ ON-FARM 설계가 데이터로 정당화된다.** AI는 '참고 판정'만 하고 확정은 거점 실물 검수가
맡는 현재 구조가 맞다. 등급을 확정하겠다고 주장했다면 이 데이터로는 뒷받침되지 않는다.
반대로 **품목 인식**은 이 데이터의 강점이므로 거기에 집중한다.

스튜디오 촬영(흰 배경·정면 조명, 1000×1000)이라 어르신 폰 사진과 도메인이 다르다.
실환경 평가셋을 따로 만들고, **대외 발표 수치는 거기서 나온 것만 쓴다.**

## 품목 정합 — 카탈로그를 데이터에 맞춘다

| ON-FARM 현재 카탈로그 | AI 허브 |
|---|---|
| 사과 · 배 · 감귤 · 양파 · 감자 | ✅ 있음 (겹치는 5종) |
| 고구마 · 건고추 · 복숭아 | ❌ **없음** |
| — | 무 · 배추 · 마늘 · 양배추 · 감 (우리에게 없음) |

학습 전에 카탈로그를 정렬하지 않으면 한바구니의 "죽은 라벨 12개"가 재발한다.
무·배추·마늘은 천안 로컬푸드 주력 품목이라 **카탈로그를 10종으로 넓히는 방향**을 권한다.
(`src/db/seed.ts`의 `SEED_PRODUCTS` + `src/ai/providers/heuristic.ts`의 `PROTOTYPES` 동시 수정)

## 수령 절차

### 1) 승인 (사용자만 가능)

1. https://aihub.or.kr 로그인
2. [농산물 품질(QC) 이미지](https://aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&aihubDataSe=data&dataSetSn=149) 접속
3. **다운로드 신청** → 활용목적 작성 → 승인 대기
4. 승인 후 마이페이지에서 **API Key 발급**(메일 수신)

승인 없이 API Key만 있으면 `HTTP 502 / "다운로드 서비스는 홈페이지에서 신청 및 승인 후 이용 가능합니다"` 가 뜬다.

### 2) 받기

```bash
curl -o aihubshell https://api.aihub.or.kr/api/aihubshell.do && chmod +x aihubshell
export AIHUB_APIKEY='발급받은키'
./aihubshell -mode l 149        # 파일 트리 (승인 없이도 조회 가능)
```

**① 라벨 전체 먼저 (약 150 MB).** 스키마·등급 분포·개체 그룹 키를 확인하는 단계.

```bash
./aihubshell -mode d -datasetkey 149 -filekey $(seq -s, 396903 396956)
```

**② 최소 검증 세트 — 배(신고) 전량, 10.5 GB.** 파이프라인 종단 확인용.

```bash
./aihubshell -mode d -datasetkey 149 -filekey 396936,396937,396938,396990,396991,396992,397044,397045,397046,397098,397099,397100
```

### 3) ⚠️ 반드시 국내에서 받아야 한다 — Colab 불가

Colab 에서 받으려다 확인한 사실:

```
Download failed with HTTP status 502.
AI 허브는 해외에서의 데이터 다운로드를 제한하고 있습니다.
```

Colab 은 해외 서버라 **다운로드가 원천적으로 막힌다**. 따라서 순서를 나눈다.

| 단계 | 장소 | 결과 |
|---|---|---|
| 수집 | **국내 PC** `tools/aihub_ingest.py` | 119 GB → 224px JPEG **약 900 MB** |
| 업로드 | Google Drive | `onfarm_cv.zip` |
| 학습 | Colab GPU | `notebooks/onfarm_train_colab.ipynb` |

디스크는 걱정하지 않아도 된다. 수집 도구가 zip 을 **1개씩** 처리하고 즉시 지우므로
최고 사용량은 원본 zip 1개(약 4 GB)뿐이다. 원본 1000×1000 PNG(832 KB)가
224px JPEG(7.2 KB)로 **0.9%** 까지 줄어드는 것을 실측했다.

```bash
# 1) 수집 (국내에서, 약 13시간 — 밤에 걸어둔다)
python tools/aihub_ingest.py --items all --key <APIKEY> --out data/onfarm_cv

# 2) 검증 + 업로드용 zip 만들기
python tools/pack_for_colab.py --data data/onfarm_cv --out data/onfarm_cv.zip
```

수집은 **끊겨도 이어받는다.** 파일키 단위로 `.ingest_state.json` 에 완료 표시를 남기고
매니페스트도 파일키마다 append 하므로, 죽은 자리에서 같은 명령을 다시 실행하면 된다.
회선이 끊기면 바깥에서 4회(30/60/90초 대기) 다시 건다 — 실제로 수집 중
`Connection was reset → DNS 실패`로 한 번 죽었기 때문에 넣은 장치다.

`pack_for_colab.py` 는 묶기 전에 (1) 매니페스트의 이미지가 실제로 있는지 (2) 개체 누출
(3) 품목 2종 이상 (4) 등급 3종 (5) 검증셋 존재를 확인하고, 문제가 있으면 zip 을 만들지 않는다.
업로드한 뒤 Colab 에서 문제를 발견하는 왕복을 막기 위함이다.

### ⚠️ aihubshell 은 조용히 잘린 파일을 남긴다

`aihubshell` 내부 `curl` 에 재시도 옵션이 없어, 전송이 끊겨도 오류 없이 "병합이 완료 되었습니다"로 끝난다.
실측 사고 두 건: 444 MB 원천이 **13.5 MB** 로, 라벨 54개가 **21개** 로 잘린 채 성공처럼 보고됐다.

`tools/aihub_ingest.py` 는 `curl --retry 8 --retry-all-errors` 로 받고
tar 앞머리·zip 무결성을 직접 검증한다. 같은 파일을 재시도 옵션으로 받으니 444 MB 전량이 정상 수신됐다.

### 원천 zip 내부 구조 (실측)

평평한 PNG 목록이며 라벨 JSON 과 파일명이 그대로 대응한다. 별도 매칭 규칙이 필요 없다.

```
pear_singo_L.zip
  ├─ pear_singo_L_25-100.png   ← 1000×1000, 약 832KB
  └─ ...
pear_singo_L.zip (라벨)
  └─ pear_singo_L_25-100.json
```

검증셋 pear_singo_L 기준 **504/504 = 100% 매칭**.

## 학습 후 접합 지점

`src/ai/providers/` 에 `CnnVisionProvider` 를 추가하고 `VisionProvider` 인터페이스만 지키면 된다.
`resolveProvider()` 의 폴백 구조와 `validateRecognition()` 스키마 검증은 그대로 통과시킬 것 —
provider 가 준 confidence 를 재검증 없이 신뢰하면 한바구니에서 겪은 게이트 우회가 재발한다.
