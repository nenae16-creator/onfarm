# ON-FARM 실행 기획서

**2026년 천안시 AI·데이터 기반 정책 아이디어 경진대회** 과제4
심사 항목 「기획력 20점」 대응 문서.

기획력은 아이디어의 크기가 아니라 **"누가, 언제, 무엇을 하고, 언제 멈추는가"** 로 채점된다.
따라서 이 문서는 확산 계획이 아니라 **중단 기준**을 먼저 적는다.

## 0. 전제 — 지금 있는 것과 없는 것

과장하지 않기 위해 먼저 구분한다. 없는 것을 있다고 쓰면 시연에서 드러난다.

| 있다 (검증됨) | 없다 (PoC 에서 확보) |
|---|---|
| 작동하는 웹 MVP (사진→후보선택→수량→등록→주문→검수→정산) | 실제 농가 사용 이력 |
| 학습된 품목 분류 모델 5종(사과·배·감귤·양파·감자) | **실제 폰 사진 성능** — 학습은 스튜디오 촬영 |
| 자동 테스트 162개, 교차검증 2회 | 거점 운영 인력·동선 합의 |
| 안전정책(신뢰도 상한·품목별 등급 게이트) | 결제·정산 실연동 |
| 표준 SKU 가격 체계 | 천안시 표준 정찰가 합의 |

**모델의 한계를 코드가 이미 강제한다.** 실환경 평가 전에는 신뢰도가 0.85를 넘지 못하고,
근거가 없는 품목은 등급을 표시하지 않는다(실제로 양파는 자동 차단 중).
PoC 의 목적은 이 상한을 **측정으로 풀어내는 것**이다.

## 1. 왜 성환인가

배 주산지이며 **천안 성환 로컬푸드 거점**이 이미 있다.
새 시설을 짓지 않고 기존 거점을 그대로 쓰는 것이 이 제안의 전제다.
시가 5년간 410억 원을 농촌공간 재편에 투자하는 흐름과도 어긋나지 않는다.

## 2. 3단계 실행

```
Phase 1 (8주)   성환 1거점 · 농가 5호        → 측정
Phase 2 (12주)  3거점 · 농가 30호            → 운영 부하 확인
Phase 3         전 거점                       → 확산
```

각 단계 끝에 **Go/No-Go** 를 두고, 기준 미달이면 다음 단계로 가지 않는다.

### Phase 1 — 성환 1거점 · 5농가 · 8주

| 주차 | 하는 일 | 산출 |
|---|---|---|
| 1 | 거점 담당자·농가 5호 선정, 표준 SKU 가격 합의 | 품목별 정찰가표 |
| 2 | 농가 방문 교육(1인 20분), 폰에 PWA 설치 | 설치 확인 5건 |
| 3–6 | **실사용 등록** — 농가가 직접 사진 촬영·등록 | 등록 건수, 소요시간 로그 |
| 3–6 | 등록 시 **실제 폰 사진** 수집 → 모델 실환경 평가셋 | 폰 사진 성능 측정치 |
| 7 | 거점 검수·출하·정산 1주기 완주 | 정산 완료 건수 |
| 8 | 농가·담당자 인터뷰, Go/No-Go 판정 | 판정 보고서 |

### Phase 1 성공 기준 (Go/No-Go)

| 지표 | 목표 | 미달 시 |
|---|---|---|
| 등록 완주율 (시작→등록 완료) | **80% 이상** | UX 재설계, 확산 보류 |
| 1건 등록 소요시간 | **3분 이내** (중앙값) | 단계 축소 후 재측정 |
| 품목 인식 정확도 (실제 폰 사진, 개체 단위) | **85% 이상** | 모델 재학습 또는 후보 개수 확대 |
| 등록 후 실제 판매 성사율 | **50% 이상** | 수요 확보 방식 재검토 |
| 거점 추가 부담 | 건당 **10분 이내** | 검수 절차 간소화 |
| 농가 재사용 의향 | 5명 중 **4명 이상** | 확산 중단 |

**어느 하나라도 미달하면 Phase 2 로 넘어가지 않는다.** 이 문장을 발표에서 그대로 말한다.

### Phase 2 — 3거점 · 30농가 · 12주

Phase 1 이 통과했을 때만 진행한다. 확인할 것은 **성능이 아니라 운영 부하**다.
거점 1곳이 하루 몇 건까지 검수·포장할 수 있는지, 인접 농가 묶음 배송이 성립하는지를 측정한다.

### Phase 3 — 전 거점

Phase 2 에서 거점당 처리 한계와 손익분기가 나온 뒤에 판단한다.
이 단계의 수치는 **지금 제시하지 않는다.** 근거 없이 확산 규모를 말하면 기획력에서 감점된다.

## 3. 역할 (RACI)

| 활동 | 농가 | 거점 담당자 | 천안시 농업정책과 | 개발팀 |
|---|---|---|---|---|
| 사진 촬영·수량 확인 | **R** | I | I | I |
| 표준 SKU 가격 결정 | C | C | **A** | I |
| 실물 검수·확정 등급 | I | **R/A** | I | I |
| 포장·출하 | I | **R** | I | I |
| 정산 | I | C | **A** | R |
| 시스템 운영·개선 | I | C | I | **R/A** |
| 성과 측정·판정 | C | C | **A** | R |

R=실행, A=책임, C=협의, I=공유

**핵심**: 농가의 R 은 **사진 촬영과 수량 확인 두 가지뿐**이다.
가격 결정도, 등급 확정도, 포장도 농가가 하지 않는다. 이것이 기존 직매장과의 차이다.

## 4. 비용 (Phase 1 기준, 범위로 제시)

정확한 견적이 아니라 **규모 감각**이다. 실제 집행은 시 예산 기준을 따른다.

| 항목 | 범위 | 근거 |
|---|---|---|
| 서버 운영 | 월 5–15만 원 | 소규모 인스턴스 1대. 모델이 기기 내에서 돌아 GPU 불필요 |
| 농가 교육 | 5호 × 20분 × 1회 | 거점 담당자가 수행, 별도 인건비 없음 |
| 거점 검수 추가 부담 | 건당 5–10분 | 기존 검수 절차에 사진 대조만 추가 |
| 포장·배송 | 기존 로컬푸드 물류 활용 | 신규 투자 없음 |
| 개발 | 추가 개발 없음 | MVP 완성, PoC 는 현행 기능으로 수행 |

**신규 하드웨어 투자가 0원**이라는 점이 이 제안의 강점이다.
농가는 자기 휴대폰을 쓰고, 거점은 기존 시설을 쓰고, 모델은 서버 CPU 에서 돈다.

## 5. 위험과 대응

| 위험 | 가능성 | 영향 | 대응 |
|---|---|---|---|
| **폰 사진에서 모델 정확도 급락** | 높음 | 높음 | 이미 예상하고 신뢰도 상한을 걸어둠. 후보 3개 제시 + 직접 선택 경로로 등록은 계속 가능. Phase 1 에서 실측해 재학습 판단 |
| 고령 농가가 앱 설치 자체를 못 함 | 중간 | 높음 | 거점 담당자가 방문 설치. PWA 라 앱스토어 절차 없음 |
| 등록은 되는데 안 팔림 | 중간 | 높음 | Phase 1 성공 기준에 **판매 성사율 50%** 포함. 미달 시 수요 확보 방식부터 재설계 |
| 거점 업무 부담 증가로 협조 거부 | 중간 | 높음 | 건당 10분 상한을 기준에 명시. 초과하면 확산 중단 |
| 등급 분쟁 (소비자 클레임) | 낮음 | 중간 | AI 는 참고값만, 확정은 거점 검수. 코드가 강제하며 화면에 표기 |
| 개인정보(농가 위치·연락처) 노출 | 낮음 | 높음 | 소비자 화면에 농가명·읍면까지만. 상세주소·연락처 미노출 |

## 6. 측정 지표 (PoC 종료 시 보고)

발표에서 "해보겠습니다"가 아니라 **"이렇게 재겠습니다"** 로 말하기 위한 목록이다.

**농가 측** — 등록 완주율, 등록 소요시간(중앙값·90분위), 재사용 의향, 미출하 회수량
**모델 측** — 폰 사진 품목 정확도(개체 단위), 후보 3개 안에 정답이 있는 비율, 직접 선택 전환율
**거점 측** — 건당 검수 시간, 반려율, 확정 등급과 AI 참고값의 일치율
**시장 측** — 등록 대비 판매 성사율, 평균 판매 소요일, 재구매율

이 중 **폰 사진 정확도**가 가장 중요하다.
현재 metadata 의 `field_evaluated: false` 가 `true` 로 바뀌는 시점이 PoC 성공의 정의다.

## 7. 데이터 관리

| 데이터 | 보관 | 비고 |
|---|---|---|
| 농가가 올린 사진 | 서버 로컬, 매물 종료 후 정리 | 외부 전송 없음 — 모델이 기기·서버 내에서 동작 |
| 등록·주문·정산 | SQLite, 시 이관 시 표준 CSV 내보내기 | 잠금 없음 |
| 실환경 평가셋 | 농가 동의 후 익명화 보관 | 재학습에만 사용, 별도 동의서 |

사진은 **외부 API 로 나가지 않는다.** 현재 구성에서 판정은 서버 안에서 끝나며,
화면에도 "사진 외부 전송 없음"으로 표기된다.

## 8. 확산 이후 (근거가 생긴 뒤에만)

Phase 3 이후 검토 대상이며 **지금은 제안하지 않는다.**
수확 전 수요예측, 기관 급식 매칭, 인접 농가 공동배송 최적화, 잉여물량 전환.
현재 DB 구조는 이를 수용할 수 있게 설계돼 있으나 **구현되지 않았다.**
